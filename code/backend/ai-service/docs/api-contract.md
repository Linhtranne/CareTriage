# CareTriage AI Service API Contract

This document locks and details the API contract between the Java backend and the Python `ai-service`. Future refactors and development cycles must strictly adhere to this schema to prevent breaking changes across triage, EHR extraction, and research flows.

---

## 🌐 Base URL & Protocol

All requests communicate over **HTTP/1.1** or **HTTP/2**. 
- **Internal Production Base URL:** `http://ai-service:8000/api`
- **Development/Local Base URL:** `http://localhost:8000/api`

---

## 🔐 Authentication & Security

All non-health endpoints require internal API key validation in production.

- **Header Name:** `X-Internal-Api-Key`
- **Value:** Configured via `INTERNAL_API_KEY` (minimum 32 characters base64 recommended).
- **Testing Override:** When `TESTING=true` is set in the environment, the internal auth check is bypassed to facilitate isolated testing.
- **Payload Limits:** Request bodies exceeding the configured `MAX_BODY_SIZE_BYTES` (default: 5MB / 16MB in development) will receive a `413 Payload Too Large` error.

## 🧬 Endpoints Contract

### 1. `POST /api/triage/analyze`
Analyzes patient symptoms during live intake. It determines if enough clinical details exist and if immediate red flags are present.

#### Request Schema
```json
{
  "session_id": "session-uuid-1234",
  "message": "Tôi thấy bị nhức đầu và sốt nhẹ từ hôm qua.",
  "conversation_history": [
    {
      "role": "user",
      "content": "Chào bác sĩ."
    },
    {
      "role": "model",
      "content": "Chào bạn, bạn đang gặp phải những triệu chứng gì?"
    }
  ],
  "attachments": [],
  "metadata": {
    "age": 28,
    "gender": "Nam",
    "onset": "1 ngày trước"
  }
}
```

*Fields Description:*
- `session_id` (String, required): Globally unique identifier for the intake session.
- `message` (String, required): Current message text sent by the user (max 4000 chars).
- `conversation_history` (Array of HistoryMessage, optional): Up to 30 past dialogue turns. Each turn requires `role` (one of `user`, `model`, `assistant`, `system`) and `content`.
- `attachments` (Array of Attachment, optional): Up to 3 base64-encoded image attachments (max 5MB each).
- `metadata` (Object, optional): Intake metadata.

#### Response Schema
```json
{
  "reply": "Chào bạn. Cho mình hỏi thêm ngoài nhức đầu và sốt ra bạn có triệu chứng đau cổ vai gáy không?",
  "is_complete": false,
  "intake_complete": false,
  "red_flag_detected": false,
  "triage_result": null
}
```

*Fields Description:*
- `reply` (String, required): The next question or advice generated by the AI for the patient.
- `is_complete` (Boolean, required): Indicator if the triage process has finished asking questions.
- `intake_complete` (Boolean, required): Flag indicating if core medical intake parameters have been fully captured.
- `red_flag_detected` (Boolean, required): Flag indicating whether any emergency red-flag conditions are suspected.
- `triage_result` (Object, optional): Detailed classification payload, generated when triage intake is complete.

      "Sốt siêu vi"

### 3. `POST /api/triage/research`
Triggers background medical research using search engines and literature indexes.
*Note:* This endpoint is only allowed if `ENABLE_WEB_RESEARCH=true` is enabled in configuration.

#### Request Schema
```json
{
  "patient_id": 4567,
  "query": "Các biến chứng lâm sàng của sốt Dengue ở người lớn có bệnh nền tim mạch"
}
```

#### Response Schema
```json
{
  "status": "Research started",
  "research_id": "research-a4f67c29be1947bca89d1b764d2719a2"
}
```

> [!WARNING]
> **Anonymization Requirement:** To guarantee privacy, `POST /api/triage/research` returns only a generated `research_id`. It must **NEVER** return or log the `patient_id` in subsequent research artifacts or telemetry logs.

### 5. `POST /api/ehr/extract-file`
Accepts a multipart file upload (`UploadFile`) of format `.pdf`, `.doc`, `.docx`, or `.txt` (max 10MB) and returns structured extracted medical entities.

#### Request Shape
- **Content-Type:** `multipart/form-data`
- **Fields:** `file` (File binary)

#### Response Schema
Same as `POST /api/ehr/extract-text`.

## ⚠️ Error Responses

Consistent error codes are returned to ensure uniform parsing by the Java Backend.

### Error Response Body
```json
{
  "message": "Dịch vụ AI tạm thời không khả dụng."
}
```

### Standard HTTP Mappings
- `400 Bad Request`: Validation failure on headers, parameters, or file constraints.
- `401 Unauthorized`: Missing or incorrect `X-Internal-Api-Key`.
- `413 Payload Too Large`: Payload exceeds the configured maximum byte size.
- `422 Unprocessable Entity`: AI safety guardrails triggered (safety blocked, inappropriate input).
- `429 Too Many Requests`: AI service rate limit or quota exceeded.
- `500 Internal Server Error`: Any internal system failure.
- `503 Service Unavailable`: Third-party AI model provider or dependencies down.

## 📋 Data Ownership & Privacy Classification

To secure integration boundaries, all fields are strictly classified below:

| Field Classification | Description | Privacy Level & Rules |
| :--- | :--- | :--- |
| **PHI (Protected Health Information)** | Raw text prompts (`message`), `conversation_history`, raw EHR clinical note (`text`), and uploaded file binary data. | **High Sensitivity:** Must never leak into telemetry, logs, or unencrypted storage. Bounded to clinical session lifecycle. |
| **Sensitive Identifier** | `patient_id` and any backend patient/account identifiers. | **Restricted:** Request-only for backend correlation. Must never be returned by research endpoints or written to logs/telemetry. |
| **Safe Metadata** | `session_id`, `research_id`, `suggested_department_code`, `urgency_level`, `confidence_score`, `processing_time_ms`, aggregate counts, latency, and token usage. | **Low Sensitivity:** Safe to process in telemetry, health metrics, and background jobs when not combined with raw PHI. |

### 📥 Java Backend Input Requirements

The Java Backend must strictly validate and provide the following inputs:
- **Triage Intake (`/triage/analyze` & `/triage/recommend`):**
  - `session_id`: Globally unique session string (1-64 characters).
  - `message`: Patient message (1-4000 characters).
  - `conversation_history`: Array of past messages (max 30 turns).
- **Background Research (`/triage/research`):**
  - `patient_id`: Numeric patient ID (strictly request-only; used for database mapping).
  - `query`: Clinical search text.
- **EHR Note Text Extraction (`/ehr/extract-text`):**
  - `text`: Non-empty clinical progression note text.
- **EHR Note File Extraction (`/ehr/extract-file`):**
  - `file`: Multipart file upload (supported types: `.pdf`, `.doc`, `.docx`, `.txt`; max 10MB).

### 📤 AI Service Generated Fields

The Python `ai-service` generates and returns:
- **Triage Intake (`/triage/analyze`):**
  - `reply` (String next question), `is_complete` (boolean), `intake_complete` (boolean), `red_flag_detected` (boolean), `triage_result` (null if incomplete).
- **Triage Intake (`/triage/recommend`):**
  - `intake_complete` (boolean), `recommendation_ready` (boolean), `missing_information` (list of questions), `reply` (null/string), `triage_result` (populated `TriageResultDetail` object).
- **Background Research (`/triage/research`):**
  - `status` ("Research started"), `research_id` (a new unique reference). **Must never return `patient_id`**.
- **EHR Extraction (`/ehr/extract-text` & `/ehr/extract-file`):**
  - `success` (boolean), `error` (masked generic error string on failure), `result` (Pydantic `ExtractionResult` containing `raw_text`, all `entities` list, categorized sub-lists of `medications`, `symptoms`, `conditions`, `dosages`, `lab_tests`, `procedures`, and `processing_time_ms`).

---

## 🛡️ PHI Data Safeguards

To maintain HIPAA/clinical safety compliance:
1. **Never Log Context/Prompts:** Raw patient messages, context notes, files, or clinical history must **NEVER** be logged in text telemetry. Only high-level event schemas (latencies, counts, model names, tokens) are written.
2. **Standardized Exception Masking:** Unhandled exceptions must be parsed through `sanitize_error` before writing logs or response bodies. This guarantees raw stack traces containing database queries or query strings are never exposed or printed.
